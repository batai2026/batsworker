# 2026-11-21 更改总结 — OpenWorker 桌面端

今天的工作是一条完整链路：**修好"选择文件夹"不弹窗 → 把它变成不能退化的断言 → 把过程写进 `AGENTS.md`**。

---

## 1. 问题是什么

打包版（74 MB 安装包）里点"选择文件夹"没有任何反应，也不报错。同一个功能在
`--no-bundle` 的 12 MB 构建里却是正常的——这个差异后来成了定位的关键线索。

## 2. 根因（两处独立故障，必须都修）

### (a) capability 没有匹配页面的 origin

打包版由 Python sidecar `openworker-server` 把 `dist/` 服务在
`http://127.0.0.1:<随机端口>/index.html` 上。端口来自 `lib.rs` 的
`TcpListener::bind("127.0.0.1:0")`，每次启动都不同。

原来的 `capabilities/default.json` 只有隐式 `local: true`，它匹配
`tauri://localhost`，**不匹配** http 远端 origin。capability 匹配失败不是"少给几个权限"，
而是**整份 capability 都不生效**——连 `core:*` 一起被拒。

这解释了那个最迷惑的现象：12 MB 构建没有 sidecar，页面是 `tauri://localhost`，
local-only capability 恰好命中。**同一份代码，加载 origin 不同。**

修法：

```json
"remote": { "urls": ["http://127.0.0.1:*"] }
```

### (b) 应用自有命令从未登记到 ACL

`build.rs` 原来只调用 `tauri_build::build()`，生成的 `acl-manifests.json` 里
**完全没有 `__app-acl__` 段**。Tauri 2 要求用
`tauri_build::Attributes::new().app_manifest(AppManifest::new().commands(&[…]))`
才会为应用命令生成 `allow-<cmd>`。

**影响面**：22 个自定义命令全都坏了，不止 `pick_folder`——自动更新、开机自启、
保持唤醒、窗口拖动、听写、安全检查等。用户只是还没点到。

### 命名规则（踩过的坑）

`pick_folder` → `allow-pick-folder`（下划线转连字符）。在 `capabilities` 里写裸命令名
`"pick_folder"` 是非法的，编译报 `invalid plugin or permission identifier 'pick_folder'`。
应用自有命令在 capability 里是**无前缀的裸权限名**，不要写 `__app__:`——
尽管 manifest 里的运行时插件键确实叫 `__app__`。

## 5. 新测试做了什么

`tests/test_tauri_acl.py` 把判定逻辑集中在单个 `problems()`，覆盖 5 类**静默**失败：

| 断言 | 若不成立 |
|---|---|
| 三张表命令集合相等（双向，多一条也算漂移） | 该命令被 ACL 拒 |
| `build.rs` 真调了 `app_manifest` | 整段 `__app-acl__` 不存在，全部命令被拒 |
| `remote.urls` 存在且是通配端口 | origin 不匹配，全部命令被拒 |
| `windows` 含 `lib.rs` 实际建的窗口标签 | capability 匹配不上，全部命令被拒 |
| 命令名不含连字符 | 生成的权限名与 `allow-*` 对不上 |

**变异验证**（关键证据，改的是 `src-tauri` 的临时副本，不碰仓库）：

```
[PASS] unmodified tree                               rc=0
[PASS] build.rs drops a command                      rc=1
[PASS] capability drops an allow-*                   rc=1
[PASS] build.rs reverts to bare tauri_build::build()  rc=1
[PASS] capability drops remote.urls                  rc=1
[PASS] capability pins a literal port                rc=1
[PASS] capability targets a renamed window           rc=1
ALL MUTATIONS CAUGHT
```

另有一个防退化用例 `test_parsers_actually_found_something`：钉住解析条数。
否则哪天 Rust 侧换写法、正则悄悄匹配空集，"三表一致"会以 `0==0==0` 的形式**通过**。

CI 无需改动：`pytest tests` 会自动收集，Ubuntu 和 Windows 两个 job 都会跑到。

## 8. 留给下次的经验（已写进 `AGENTS.md` §8）

- **判断"ACL 到底拒了没有"，看错误的形状**：
  - `not allowed by ACL` → 卡在 ACL，capability 没匹配上或权限没登记；
  - `invalid args / missing required key` → 已穿过 ACL 进入参数解析，**ACL 是通的**。
  这条把"猜"变成了"测"。
- **安装包体积是信号**：12 MB 与 73 MB 的差异就是"有没有 sidecar + dist"，
  也就是"页面从哪个 origin 加载"。排查 Tauri ACL 问题，先看包大小。
- **capability 被编译进二进制**（`generate_context!`），改安装目录里的 json 毫无作用，
  必须重新编译 Rust。
