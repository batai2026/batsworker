## 1. 快速上手

### 1.1 安装

从 [openworker.com](https://openworker.com) 下载对应平台的安装包：

| 平台 | 说明 |
|---|---|
| macOS (Apple Silicon) | 已签名 + 公证 + 自动更新 |
| Windows 10/11 (x64) | 未签名（SmartScreen 会提示——点"仍要运行"） |

安装后打开 OpenWorker，首次启动会进入设置向导。

### 1.2 设置向导（三步）

**第一步：选择模型提供商。** 你需要至少一个 API key 才能使用 OpenWorker。从列表中选择一个（OpenAI、Anthropic、GLM/Z AI、DeepSeek、Ollama 本地模型等），粘贴你的 API key。key 只保存在这台电脑上。

> **没有 key？** 可以先跳过设置，但大部分功能需要模型才能工作。

**第二步：连接日常工具。** 登录 OpenWorker Cloud 即可一键连接 Slack、GitHub、Gmail 等 20+ 工具——无需开发者控制台、无需手动粘贴 token。也可以点"不登录继续"，之后再在"连接器"页面逐个配置。

**第三步：开始使用。** 选择"创建你的第一个自动化"（用模板快速上手）或"开始使用协作者"（直接开一个会话）。

### 1.3 发出第一条消息

底部输入框直接打字，按 Enter 发送。协作者会拆解任务、调用工具、给你最终结果。

试试这些：
- "分析这个文件夹里的文件，总结重点内容"
- "阅读这个项目并给出 5 条要点概览"
- "找出并修复失败的构建"

## 2. 主界面

```
┌────────────────────────────────────────────────────────────┐
│ [侧边栏]          │  会话标题 · 模型 · 文件夹              │ [右侧栏]

│ ✓ 新会话          │  用户: 帮我分析这个项目               │  ▸ 进度
│ 🔍 搜索           │  Agent: 这个项目包含…                 │  ▸ 产物
│ ⏱ 自动化          │  ⚙ write_file — OK                   │  ▸ 检查点
│                   │  ⚙ read_file  — OK                   │  ▸ 文件
│ 已置顶            │  Agent: 总结如下…                     │  ▸ 团队
│ 最近              │                                       │  ▸ 访问权限
│  · 会话 A         │  ┌─────────────────────────────────┐  │
│  · 会话 B         │  │ 💬 问问协作者…  [+] [模型] [▶]  │  │
│ ── 计划任务 ──    │  └─────────────────────────────────┘  │
│ ── 自动化 ──      │                                       │
│                   │                                       │
│ [👤 账户]         │                                       │
└────────────────────────────────────────────────────────────┘
```

### 侧边栏

- **新会话**：开一个新对话
- **搜索**：搜索所有会话（⌘K 或点搜索）
- **自动化**：定时任务和目标守护
- **最近**：按时间排序的会话列表，点标题栏的滑块可按协作者分组和筛选
- **已置顶**：你手动置顶的会话
- **账户行**（底部）：登录状态、收件箱徽章、账户菜单（收件箱/连接器/设置/活动）

### 右侧栏

右侧栏是"这个会话能触碰到什么"的一站式面板，包含：

| 区域 | 内容 |
|---|---|
| **进度** | 正在执行的多步任务的当前状态 |
| **看板** | 团队协作看板的摘要（仅团队会话） |
| **团队** | 团队成员列表和聊天入口（仅团队会话） |
| **产物** | 本次会话生成的文件，点击可预览 |
| **检查点** | 每个回合的文件快照，可一键回滚 |
| **日志簿** | 团队的知识记录（仅团队会话） |
| **文件** | 会话可访问的所有目录 |
| **访问权限** | 来源（连接器）和文件夹的开关 |

### 顶部栏

- **左侧**（侧边栏收起时显示）：[显示侧边栏] [+ 新会话] [搜索]
- **中间**：会话标题 + 事实副标题（模型 · 文件夹）
- **右侧**：产物按钮（有新产物时出现）+ 侧栏切换

## 3. 协作者（Coworker）

协作者（Coworker）是针对特定角色或任务特化的 agent。默认的 **Coworker** 是通用型协作者，适合大多数任务。

### 3.1 切换协作者

在输入框上方的 **协作者标签**（会话设置行）点击，或按 `⌘K` 打开搜索。选择一个已启用的协作者即可。

内置协作者：
- **Coworker**（默认）：通用型，适合文件分析、草稿、调研、构建
- **Chat**：纯聊天，无文件系统访问
- **Code**：需要绑定一个 git 仓库，专注代码工作

安全类协作者（security、appsec-worker、dep-audit 等）和 DevOps 类协作者（devops-lead、infra-worker 等）可以在设置中启用。

### 3.2 安装更多协作者

在设置 ▸ 协作者页面，或通过输入框的"导入协作者…"：

1. **从 GitHub 导入**：粘贴仓库 URL
2. **从文件夹导入**：选择本地目录
3. **从 zip 导入**：选择 .zip 文件

安装时会弹出**同意清单**，明确列出该协作者能做什么（工具、风险等级、连接器、MCP 服务器）。协作者安装后默认禁用——你需要审阅能力清单后手动启用。

**签名验证**：如果包附带 minisign 签名，同意界面会显示验证状态（✓ 已签名 / ✕ 校验失败 / 已签名·密钥未验证）。

### 3.3 管理已安装的协作者

在设置 ▸ 协作者页面：
- **启用/禁用**：切换开关
- **删除**：从 ⋮ 菜单删除（会话历史保留）
- **导出**：打包为 zip 分享给他人

## 4. 会话与工作区

### 4.1 会话生命周期

每个会话是一个独立的对话线程，有自己的文件夹、协作者、模型和记忆。

- **新建**：侧边栏"新会话"按钮或 `⌘N`
- **切换**：侧边栏点击任意会话
- **重命名**：会话行的 ⋮ 菜单 → 重命名
- **置顶**：⋮ 菜单 → 置顶
- **归档**：⋮ 菜单 → 归档（可在"已归档"分组中找回）
- **删除**：⋮ 菜单 → 删除（需二次确认）

### 4.2 工作区（文件夹）

**Coworker** 协作者自动获得一个临时文件夹（scratch dir），用于存放会话产物。临时文件夹的路径不会显示——用"临时文件夹"代替。

**Code** 等项目级协作者必须选择一个项目文件夹。你可以：

- 在**会话设置行**（输入框上方）点击文件夹标签选择
- 在发送时弹出对话框选择（UX-029：文件夹强制在发送时而非会话开始时）
- 使用**临时文件夹**——发送时自动创建，git 已初始化，之后可以"保存为项目"

### 4.3 保存临时会话为项目

临时会话的产物可以保存到真实位置：点击标题区的"保存为项目…"链接，选择目标文件夹。会话会自动重连到新路径，转录保持不变。

### 4.4 授予更多文件夹

在右侧栏 ▸ 访问权限 ▸ 文件夹区域点"+ 授予文件夹访问权限…"。默认只读——勾选"允许写入"后 agent 才能修改该文件夹中的文件。

## 5. 与 Agent 协作

### 5.1 输入框

底部输入框支持：
- 纯文本消息（Enter 发送，Shift+Enter 换行）
- **拖放或粘贴文件**（图片、PDF、代码文件等作为附件）
- **/ 技能快捷方式**：输入 `/` 弹出技能列表，选择后自动填入前缀
- **回复调整提案**：当团队提案或计划卡片等待审批时，直接打字即可附反馈

### 5.2 模型切换

输入框右下角的模型标签可以随时切换模型——会话中途换模型是安全的（历史自动转换）。在设置 ▸ 模型中勾选要在选择器中显示的模型。

### 5.3 模式

输入框左下角的模式标签控制权限级别：

| 模式 | 含义 |
|---|---|
| **讨论** | 只读——不编辑文件、不执行命令 |
| **请求批准** | 每次编辑和命令都需要你批准（默认） |
| **自动批准** | 会话模型自动审批常规操作，有疑虑仍会问你 |
| **绕过审批** | 全部直接执行——审批关闭（慎用） |

### 5.4 转录（Transcript）

转录是会话的核心视图：

- **你的消息**：右侧蓝色气泡
- **Agent 回复**：左侧白色气泡（支持 markdown）
- **步骤组**：折叠为"N 个步骤"的灰色区块——点击展开可看到每一步的工具调用和结果
- **审批卡**：需要你决策的操作（允许一次/始终允许/拒绝）
- **通知**：灰色状态行（错误、模型切换、上下文压缩等）
- **记忆通知**：agent 保存记忆时的提示，带"撤销"按钮

### 5.5 中途修正（Steering）

在 agent 正在执行时打字不会排队为新消息——而是作为**转向上下文**注入到当前回合，agent 会看到你的补充并据此调整方向。

### 5.6 停止与重试

- **停止**：agent 执行中点"⏹ 停止"按钮
- **重试**：出错时错误通知右侧出现"重试"按钮

## 6. 权限与审批

### 6.1 审批卡

当 agent 要执行需要批准的操作时，输入框上方会出现一张**审批卡**，包含：

- 操作的**人类可读描述**（如"写入文件 `output.md`"）
- 作用范围（"仅在本机"或"离开本机 → Slack"）
- 操作内容预览
- 按钮组

### 6.2 按钮选择

| 按钮 | 效果 |
|---|---|
| **允许一次** | 本次执行，下次仍会问 |
| **始终允许** | 本会话内同类操作不再询问 |
| **始终允许此命令** | 仅限 shell 命令：本会话内精确匹配此命令不再问 |
| **允许只读命令** | 自动放行所有只读命令（本会话内） |
| **拒绝** | 不执行；agent 会收到拒绝通知 |

### 6.3 评审员（Auto-Approve 模式）

启用"自动批准"模式后，你的会话模型会审查每个操作：

- **常规操作**被自动放行（转录中显示"✓ 自动批准"标签）
- **有疑虑的操作**仍然弹出审批卡（显示"评审员不确定：…"）
- **被拦截的操作**显示"已被评审员拦截"卡片，附完整原因和"仍然允许"按钮
- 连续 5 次拒绝会暂停评审员——之后的审批直接交给你

**预算保护**：在设置中可以配置自动化和会话的 token 预算。达到上限时运行会优雅停止而不是继续消耗。

### 6.4 硬底线（不可绕过）

以下操作**永远**需要人工批准，任何模式都不能绕过：
- 修改 OpenWorker 自身的设置和密钥
- 写入 `.git/hooks`（延迟执行的代码）
- 创建或修改定时任务（安装未来行为）
- 运行本回合内下载的文件（防"取回即执行"攻击）

## 7. 浏览器自动化与录制

### 7.1 基本浏览器操作

Agent 可以通过 Playwright 驱动一个本地浏览器：

- `browser_open_url` — 打开网页
- `browser_read_page` — 读取页面文本和控件
- `browser_click` / `browser_type` / `browser_select` — 交互
- `browser_screenshot` — 截图

这些工具按 EGRESS 风险分类——首次使用会请求批准。

### 7.2 录制浏览器操作

当 agent 完成了一连串浏览器操作后，你可以把这些操作**录制为可回放的脚本**：

1. 对 agent 说："帮我录制刚才的浏览器操作"或手动调用 `browser_record_start`
2. Agent 继续执行浏览器操作——每次成功的操作自动记录
3. 完成后说"停止录制并保存"
4. 之后可以对 agent 说"回放 xxx 流程"来重新执行

回放是**确定性**的——精确重执行每一步。如果某一步失败（元素不见了、页面结构变了），回放停止并报告失败步骤，agent 可以自修复后重新回放。

### 7.3 管理已保存的录制

右侧栏的浏览器会话中，或对 agent 说"列出已保存的浏览器录制"即可查看所有已保存的回放脚本。

## 8. 自动化（定时任务与目标守护）

自动化让 agent 在你不在场时也能工作。有两种触发方式：

### 8.1 定时任务（Cron）

按时间表周期执行。创建方式：

1. **对话式**：对 agent 说"每天早上 7 点给我一份晨报"
2. **手动**：自动化页面点"+ 新建自动化"
3. **模板**：从"从模板开始"区选择（GitHub 摘要、晨报、收件箱摘要等）

每次运行是一个真实的、持久化的会话——你可以在运行历史中打开它查看 agent 做了什么并继续追问。

### 8.2 目标守护（事件触发）

除了定时之外，还可以设置**事件条件**——"当某事发生时"自动触发：

| 触发器 | 示例 |
|---|---|
| **文件** | "当 build.log 里出现 ERROR 时通知我" |
| **看板状态** | "当看板条目阻塞超过 2 小时时提醒我" |
| **收件箱** | "当收件箱有待处理的审批时 ping 我" |

创建方式：对 agent 说"帮我盯着 build.log，出现 ERROR 就分析原因并修复"。Agent 会创建一个带触发器的自动化。

**冷却**：条件持续为真时不会连续触发——默认间隔 1 小时。

### 8.3 预算

每个自动化可以设置 **token 预算**——当累计消耗达到上限时，运行会优雅停止而不是继续消耗。创建时对 agent 说"预算 20 万 token"或手动设置。

### 8.4 运行通知

自动化开始运行时会弹出 5 秒通知（右上角），点"查看运行"直接跳到运行会话。

### 8.5 免询问放行

自动化可以携带**常设批准**（standing approvals）——比如"允许向 Slack 频道 #reports 发消息"。这些在创建审批卡上列出，批准后自动生效。可以在自动化详情页随时撤销。

## 9. 收件箱（Inbox）

收件箱是**跨会话的待处理队列**——当 agent 需要你的决策但你不在线时，审批和提问会停靠在这里。

### 9.1 查看收件箱

侧边栏的收件箱徽章（有待处理项时出现）或账户菜单 → Inbox。

### 9.2 处理待办项

每个收件箱卡片包含：
- 来源会话标签（点击可跳转到原会话）
- 操作内容（审批卡、提问选项、目录请求等）
- 决策按钮

**先到先得**：无论你从收件箱、会话内还是 Slack 处理，第一个响应的通道生效。

### 9.3 远程处理

登录 OpenWorker Cloud 后，收件箱项会镜像到配置的 Slack 频道——你可以直接在 Slack 中回复来处理审批。

### 9.4 路由配置

在收件箱 ▸ 配置页签：
- **镜像频道**：无人值守会话的审批按钮投递到哪个 Slack 频道
- **私信路由**：哪个会话处理发给 bot 的私信
- **频道订阅**：哪些会话监听哪些频道
- **未路由**：无法投递的消息（不会丢失）

## 10. 记忆

协作者可以在对话之间记住关于你的有用信息。

### 10.1 保存记忆

当你在聊天中提到一个持久偏好时，agent 会自动保存并显示通知——"我会记住这一点"，带撤销按钮。

你也可以明确说"记住我偏好暗色主题"。

### 10.2 查看和管理

设置 ▸ 记忆 页面列出所有已保存的记忆：
- **编辑**：点击铅笔图标修正错误
- **删除**：点击垃圾桶图标删除单条
- **全部忘记**：一键清除全部

### 10.3 你的指令

设置 ▸ 记忆 ▸ "你的指令"文本框——写在这里的规则**凌驾于自动记忆**之上，且 agent 永远不能修改。例如：

```
我使用屏幕阅读器——不要用表格，描述任何图片
日期使用 DD-MM-YYYY 格式
```

### 10.4 关闭记忆

关闭"记住关于我的新信息"开关后 agent 停止保存新记忆，但已有的记忆仍会使用直到你删除。

## 11. 文件与产物

### 11.1 产物（Artifacts）

Agent 在会话中创建的文件（报告、代码、HTML 页面等）会出现在右侧栏的"产物"区域。点击可内联预览：
- Markdown 和代码文件直接渲染
- HTML 在沙箱化 iframe 中显示
- 图片直接显示
- CSV/Excel 以表格显示
- PDF 逐页渲染
- Office 文档提示用默认应用打开

### 11.2 文件操作

产物区域每个文件支持：
- **打开**：点击预览
- **复制内容**：⋯ 菜单
- **复制路径**：⋯ 菜单
- **在浏览器中打开**：HTML 文件
- **用默认应用打开**：表格/PDF/Office 文件
- **在文件管理器中显示**：⋯ 菜单

### 11.3 文件访问

右侧栏 ▸ 访问权限 ▸ 文件夹区域管理会话的目录：
- **临时文件夹**（Coworker 默认）：读写

每个文件夹可以单独切换只读/读写。

## 13. 团队协作（多 Agent）

对 agent 说"帮我组建一个团队来处理这个项目"。负责人会提出人员配置方案（哪些协作者、什么模型、为什么），你批准后团队自动创建。

### 13.4 日志簿

团队在执行过程中的发现、证据和决策记录在日志簿中——比看板更持久，跨会话保留。

### 13.5 开放表面

看板不仅限于 OpenWorker 内部使用：
- `ocw board …` CLI 命令
- `ocw board mcp` stdio MCP 服务器（外部编码 agent 可加入）

## 17. 隐私与安全

OpenWorker 的隐私模型非常简单：**一切都在你的电脑上**。

- Agent 循环、对话、连接器 token、模型 key——全在本机
- 唯一的云组件是 OAuth 代办（可选）和中继（可选）
- 不发送遥测、不收集使用数据
- 浏览器内的 HTML 产物在无网络沙箱中渲染

安全模型：

| 层级 | 机制 |
|---|---|
| **权限引擎** | 每次工具调用按风险分类 + 模式 + 白名单判定 |
| **审批卡** | 写入、执行、出网操作需要人工批准 |
| **硬底线** | 某些操作永远需要人工，不可被模式或白名单绕过 |
| **出口策略** | 出网域名白名单持久化；`request_egress` 申请加白，批准后自动放行 |
| **来源追踪** | Agent 本回合下载的文件再次执行时强制人工确认 |
| **预算护栏** | Token 消耗达到上限时优雅停止 |
| **签名分发** | Persona 包可附带 minisign 签名验证 |

## 19. 常见问题

**Q: Agent 在执行中我能做什么？**
可以随时打字补充方向（steering）。也可以点停止按钮中断。

**Q: 断线了怎么办？**
会话和所有状态都持久化在本机。重新打开 OpenWorker 后从侧边栏选择会话继续。

**Q: 无人值守的任务卡在审批上怎么办？**
审批会停靠在收件箱。打开收件箱处理即可，agent 会继续执行。也可以在 Slack 上远程处理。

**Q: 怎么让 agent 记住我的偏好？**
直接在聊天中说"记住…"或"我喜欢…"，agent 会保存。也可以在设置 ▸ 记忆 ▸ "你的指令"中写持久规则。

**Q: 界面是英文的怎么切换中文？**
设置 ▸ 通用 ▸ 界面语言 → 中文（简体）。首次启动会自动跟随系统语言。

**Q: 怎么让 agent 定时执行任务？**
直接说"每天早上 7 点给我一份报告"或"当 build.log 出现 ERROR 就通知我"。Agent 会创建对应的自动化。

**Q: 怎么回滚 agent 做的文件修改？**
右侧栏 ▸ 检查点区域列出每个回合的文件快照——点回滚按钮即可恢复到该回合结束时的状态。

**Q: Token 用量怎么看？**
输入框右下角的用量标签显示当前上下文占用。点击查看明细。自动化可以设置预算上限。

**Q: 怎么添加自定义工具？**
通过 MCP 协议接入——在连接器页面的 Custom · MCP 区域添加任何 MCP 兼容的服务器。

**Q: 界面上有些文字还是英文的？**
主流程已完全中文化。部分次级页面（连接器详情页、Persona 详情页、看板全屏等）仍在翻译中——这些页面的功能不受影响。

## 20. 评测与回放（开发者向）

> 面向想横向对比模型或协作者（harness）表现的进阶用户与开发者。
> 设计细节见 [design/eval-and-replay.md](design/eval-and-replay.md)。

OpenWorker 为每个会话记录一份**轨迹账本**（只含摘要与指纹，不含正文与密钥），它是分叉、回放与离线评测的共同基础。

### 20.1 把真实会话导出为评测用例

```powershell
python -m coworker.eval.capture <会话ID> --out <输出目录>
```

- 会话 ID 即会话数据文件名（`<数据目录>/conversations/<会话ID>.jsonl`）。
- 导出两个文件：`messages.jsonl`（每轮用户输入一行）与 `baseline.json`（每轮的模型、出站字节数、请求数、工具调用序列——作为后续对比的参照基线）。
- **隐私门禁**：如果该会话曾接触过密钥（账本中存在脱敏标记），导出会被拒绝；确认无误后可加 `--force` 强制导出。

### 20.2 跑「模型 × harness」矩阵

```powershell
# 直接消费导出的用例包
python -m coworker.eval.matrix --case <用例目录> --models openai:gpt-5.6-sol,anthropic:claude-opus-4-8 --harnesses minimal,code --out report.json

# 或者直接从会话读取
python -m coworker.eval.matrix --session <会话ID> --models ... --harnesses minimal
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--harnesses` | 逗号分隔的 harness id：内置 `minimal / code / creator / code-mode`，或任何已安装协作者的 id |
| `--stub` | 用确定性假模型离线自测（不联网、不消耗额度），用于验证流程 |
| `--auto-approve` | 自动批准工具调用（无人值守跑工具时才开；默认全部拒绝） |
| `--max-turns N` | 只重放前 N 轮 |
| `--check-baseline` | 把基线对比变成门禁：任何漂移都让命令失败（需要配合 `--case`） |
| `--max-bytes-ratio` | 门禁允许的出站字节相对偏差，默认 0.10（10%） |
| `--write-baseline` | 用本次 `--stub` 运行重写用例的 `baseline.json`（刷新黄金基线；需同时给 `--case` 与 `--stub`，且只允许单格） |
| `--out` | 报告 JSON 输出路径 |

报告中每个「模型 × harness」格子都附带 `vs_baseline` 对比（逐轮的字节数差异与工具序列是否一致）。**默认基线只是参照，不会判定通过/失败**；加上 `--check-baseline` 后，工具序列不一致、字节偏差超阈值、基线缺轮或执行报错都会判为失败，命令以退出码 `3` 结束（退出码 `1` 仍表示矩阵执行本身有格报错，`2` 表示参数错误），可直接接入 CI。

仓库自带一个确定性黄金用例 `evals/ci-case/`：`.github/workflows/eval.yml` 在每次 push / PR 用 `--stub --check-baseline` 跑它（漂移即失败），另有一个手动触发的 `workflow_dispatch` 任务用仓库密钥跑真实模型矩阵。有意修改系统提示、harness 或工具目录后，需要刷新黄金基线——**必须使用空的工作区与空的状态目录**，否则工作区绝对路径、git 状态、已装技能都会进入出站负载，造成假漂移：

```powershell
$env:COWORKER_STATE_DIR = "$env:TEMP\eval-ci-state"
New-Item -ItemType Directory -Force "$env:TEMP\eval-ci-state", "$env:TEMP\eval-ci-ws" | Out-Null
python -m coworker.eval.matrix --case evals\ci-case --stub --workspace "$env:TEMP\eval-ci-ws" --write-baseline
```

### 20.3 分叉与回放（API）

- `POST /v1/sessions/{id}/fork` `{"turn": N}`：在第 N 轮之前切开，复制出一个新会话（不携带 turn 则整体复制）。只复制会话状态，不复制工作区文件。
- `POST /v1/sessions/{id}/replay` `{"input": "..."}`：在分叉出的会话上重放输入；不带 input 时自动重放切割点那一轮的用户输入。
- `GET /v1/sessions/{id}/trajectory/diff?other=<会话ID>`：逐条对比两个会话发往模型的请求指纹，验证回放是否一致。
