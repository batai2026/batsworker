## 1. 本轮任务与结论

任务是回答「v1.0.6 和 v1.0.5 的程序，有哪些区别」。直接读 180 个提交不可行，改为**先定版本边界，再按目录聚合 diff，最后抽验具体改动**。

一句话结论：**这不是一次「功能版本」，而是一次「内部重构 + 安全加固 + 依赖大版本跟进」**。对外 API 面完全没变（215 条 HTTP 路由逐条一致），但修了 6 处安全问题、换了 SPA 的加载方式、并把前端依赖跨了三个大版本。发布说明只写了依赖治理和文档，**把安全修复和功能新增全漏了**。

判断依据全部可复算，见 §11。

## 2. 版本边界：先钉死「v1.0.6 是什么」

这一步是整轮工作的前提，也是上一轮踩过的坑（把没打的标签当成已发布）。

| 事实 | 值 | 复核命令 |
|---|---|---|
| `v1.0.5` 标签 | `aa9e540`，2026-11-09 | `git log -1 --format='%h %ad' --date=short v1.0.5` |
| HEAD | `20364b2`，2026-11-19 | `git log -1 --format='%h %ad' --date=short HEAD` |
| **本地 `v1.0.6` 标签** | **不存在** | `git tag --list 'v1.0.6'` → 空 |
| 本地已有标签 | `v1.0.5-rc1`、`v1.0.5`、`v1.0.4` … `v1.0.0` | `git tag --list 'v1.0.*' --sort=-v:refname` |
| 窗口内提交数 | **180** | `git rev-list --count v1.0.5..HEAD` |
| 三处版本号 | `pyproject.toml` / `tauri.conf.json` / `package.json` 均为 `1.0.6` | 见 §11 |

**结论**：`v1.0.6` ≡ HEAD `20364b2`，不是标签，是一个**只存在于工作树版本号里的版本**。因此差异窗口只能定义为 `v1.0.5..HEAD`，而不是「两个标签之间」。

> 教训：回答「两个版本有什么区别」之前，先确认两个端点是否都是真实存在的引用。仓库里版本号已经 bump 但没有对应标签，是最容易把结论说过头的地方。

命名三件套也别混：产品名 **OpenWorker**、仓库 `batai2026/batsworker`、Python 发行包 **coworker**、工作目录 `openworker-0.2.1`（目录名停留在 0.2.1，与当前 1.0.6 无关）。

## 4. 结构性改动：拆分，不是新增功能

`coworker/` 的 +10117 行看着像新功能，实际是**大文件拆分**。判定方法不是看行数，而是看**端点守恒**：

- v1.0.5 `app.py`：2812 行 → HEAD 128 行
- v1.0.5 `integration_tools.py`：4519 行 → HEAD 239 行
- 新增 35 个文件（含 `server/routes/` 25 个、`connectors/tools_*.py` 7 个）

**守恒证明**（两侧独立统计，非相减）：

| 项 | v1.0.5 | HEAD |
|---|---|---|
| HTTP 路由（`@app/router.get/post/put/patch/delete`） | 215 | 215 |
| WebSocket 装饰器 | 2 | 2 |
| 新增端点 | — | 0 |
| 消失端点 | — | 0 |

`tests/data/route_inventory.txt` 记 220 条，与 215 的差额可逐项解释，不是矛盾：

```
215 条代码路由 − 1 条 COWORKER_DEBUG_INJECT 门控（默认不注册）
            + 4 条 FastAPI 自带（/openapi.json、/docs、/docs/oauth2-redirect、/redoc）
            + 2 条 WebSocket
            = 220
```

守卫本身也同步长出来了：`tests/test_route_inventory.py`（快照式，`--update` 的 diff 就是 API 变更）、`tests/test_integration_tool_catalog.py`（136 条工具目录快照）、`tests/test_frontend_spa.py`（SPA 兜底不得越出 dist 根、未知 API 路径必须 404）。测试文件 158 → 172。

> 也就是说：**这次重构是可验证的**，不是「看起来搬过去了」。上一轮 worklog（`docs/archive/worklog-2026-11-12.md`）记录了拆分过程，本轮是事后独立复核，两边结论一致。

## 5. 用户可感知的变化

### 5.1 SPA 改由 sidecar 同源提供（`4e97daa` + `c5189c6`）

webview 不再加载 Tauri 内嵌副本，改为 `http://127.0.0.1:<port>/index.html`——与 API 同源，绕开 Tauri 2.11 在 Windows 上的内嵌服务器死锁，同时去掉每次 API 调用的跨源跳转。

配套四个细节，值得记下来因为都是**踩过才写的**：

1. `dist/` 作为 bundle resource 打包，用 `--frontend-dist` 交给 sidecar。
2. 启动前 `wait_for_port` 等端口，**预算 15 秒**。原来是 4 秒，实测冷启动 PyInstaller onedir 需 6.53 秒——4 秒会把健康启动误降级成内嵌副本，开发构建下解析到 dev server，**白屏**。
3. 内嵌副本只是兜底路径；`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`（放开 mixed-content 与 private-network 检查）**只在那条兜底路径上设**，因为只有它会从 `https://tauri.localhost` 打 loopback API。
4. URL 用 sidecar **实际绑定的端口**拼接，不用字面量——否则注入的 API token 会送给抢占该端口的进程。

### 5.2 启用严格 CSP（原来 `csp: null`）

新增策略锁死 `default-src 'self'`，`connect-src` 只放 `ipc:`、`http://ipc.localhost`、`127.0.0.1` 的 http/ws；`object-src 'none'`、`base-uri 'self'`、`frame-ancestors 'none'`。前端无外链字体或 CDN（已 grep 确认），不影响渲染。

### 5.3 依赖大版本

| 包 | 1.0.5 | 1.0.6 | 连带改动 |
|---|---|---|---|
| `pdfjs-dist` | ^4.10.38 | ^6.5.438 | `RightRail.tsx` 渲染参数 `canvasContext` → `canvas`（v6 API） |
| `tailwindcss` | ^3.4.19 | ^4.3.5 | `tailwind.css` 从 `@tailwind` 三条指令改为 `@import "tailwindcss"` + `@theme` 24 个色标；`autoprefixer` 移除 |
| `vite` | ^6.4.5 | ^8.3.8 | `@vitejs/plugin-react` 4.3.1 → 6.3.0 |
| Python 基础镜像 | `3.12-slim` | `3.15-slim` | `site-packages` 路径同步 |
| stt crate | — | — | `ureq` 2→3.5、`cpal`→0.18.2、`sha2`→0.11 |

`package.json` 新增 `"engines": { "node": "^22.13.0 || >=24.0.0" }`，配合仓库既有的 `engine-strict=true`——**这条意味着 Node 20 装不上前端依赖**，不是可选建议。

> Tailwind 4 迁移里有个值得抄的注释：`@config` 逃逸口在本项目**静默失效**——构建成功、股票工具类全都 emit，但应用实际用的 21 个颜色工具类（`bg-panel`、`text-ink`、`hover:bg-chromeHover`…）编译成空。改成 v4 原生 `@theme` 才生效。**「构建成功但样式没了」是 Tailwind 4 升级的默认故障模式**。

## 6. 安全修复：六条，发布说明一条未提

这批是本轮最意外的发现。逐条：

| 提交 | 内容 | 为什么是安全问题 |
|---|---|---|
| `ef63a75` | egress 白名单拒绝公共后缀与裸 IP | `is_allowed` 是「主机或任意子域」匹配，一次批准 `com` / `co.uk` 就等于批准整个命名空间；改为要求至少两个标签 |
| `f3313f0` | `egress-policy.json` 列为受保护设置 | 否则 agent 自己就能扩权 |
| `a067ca6` | Docker 状态目录移出 `/workspace` | `/workspace` 是 agent 的会话根，`read_file` 只校验「在会话目录内」——状态目录放在那里，模型无需审批就能读 `secrets.json`（连接器凭据）与 `sidecar-<port>.token`（完整本地 API token） |
| `2b8cb2a` | PDF 体积上限下沉到解码处 | 原来只在校验处（`inspect()` 与 attach 路径），未来第四个调用者会把无界解码带回来 |
| `ce6b613` | `inspect-pdf` 在 base64 解码前限体积 | 解码后再校验，等于先付 4/3 倍内存分配 |
| `c5c8a03` | zip 条目用 `is_relative_to`，不用字符串前缀 | `startswith` 让 `/root/app-evil` 通过 `/root/app` 的检查（Zip Slip） |

`2b8cb2a` 的提交信息把取舍写得很清楚：上限取两条路径中较松的 16M（attach 侧是 15M），**保证今天能附上的输入一条都不变**。这是「修安全问题不顺手改变用户可见行为」的正确做法。

## 8. 本轮新增教训（AGENTS.md 候选）

按 AGENTS.md 的收录门槛（同一类错误至少发生两次），本轮只有第一条够格直接进台账，其余先记在这里观察。

### 8.1 够格：对外说「两个版本的区别」之前，先验证两个端点都是真实引用

同类已发生两次：一次是把未打的标签当成已发布（本轮 §2，`v1.0.6` 无标签）；一次是 CHANGELOG 的计数在发布说明落笔后失效（§7.1）。共同点——**结论基于一个没有当场复核的引用**。

规则：版本差异类问题，第一步固定为「确认两端 ref 存在 + 取版本窗口提交数」，把数字先钉在报告开头，后面所有结论都以它为准。

### 8.2 观察中：重构的验收标准是「对外面守恒」，不是「行数搬完了」

本次 `app.py` 从 2812 行降到 128 行，属于极端拆分。验收不能看 diff 是否「看起来像搬运」，要用独立手段证明对外行为不变——本轮用「两侧各自统计路由集合再逐条比对」，而不是「新增数减删除数」（后者会因一增一删互相抵消而假阴性）。

观察到第三次这类需求时再进台账。

### 8.3 观察中：发布说明要从提交里反向核对，不能只信自己写的那段

CHANGELOG 漏掉了 6 处安全修复和 1 个新功能，原因很可能是按「本次主要精力在哪」来写，而不是按「窗口内所有 `feat`/`fix` 提交」来核对。

规则候选：发版前跑一次 `git log --grep='^feat|^fix' v<prev>..HEAD`，逐条确认「已写进 CHANGELOG / 明确判为不写」，而不是凭印象。本轮就是这样发现缺口的。

## 9. 未决事项

### 9.1 Tauri 远程 origin 下的 IPC 是否仍可用（**未验证，需实测**）

SPA 从 `tauri://localhost`（及 Windows 的 `https://tauri.localhost`）改为 `http://127.0.0.1:<port>`，但 `src-tauri/capabilities/default.json` 里只有：

```json
{ "windows": ["main"], "permissions": ["core:default", "..."] }
```

**没有 `remote` 段**。按 Tauri v2 的模型，从远程 URL 加载的 webview 需要显式声明 `remote.urls` 才被授予 IPC 权限。若属实，`invoke()` 会被拒绝，受影响的是**非 HTTP 路径的功能**：麦克风（语音输入）、更新横幅、窗口隐藏/显示/置顶。

我没有实测 GUI，只实测了 sidecar（`smoke_sidecar.ps1`）。所以这一条记为**待确认**，不记为缺陷——也可能 Tauri 对 loopback 有豁免，或 `withGlobalTauri` + 初始化脚本的路径不受此限。

确认方法（任选其一）：

1. 装 `OpenWorker_1.0.6_x64-setup.exe`，打开设置里的语音输入，看是否报 IPC 错误；
2. Chrome/Edge 里开 `http://127.0.0.1:<port>/index.html` 对照——浏览器里 `__TAURI__` 不存在，界面应当**不显示**麦克风按钮；桌面端如果也不显示，说明是能力位被拒，不是功能缺失。

若确认被拒，最小修法是在 `capabilities/default.json` 加：

```json
"remote": { "urls": ["http://127.0.0.1:*"] }
```

——但这等于把 IPC 暴露给任何本地端口，需要权衡；替代方案是只在兜底路径（内嵌副本）下才需要这份能力，或干脆放弃远程 origin 方案、回到 `c5189c6` 的 15 秒等待 + 内嵌副本。

**这条应在下一个 release 前解决。**

## 10. 环境与命令踩坑

本轮新踩到的（AGENTS.md §6 已有两条，这里补三条）：

1. **`$x = Select-String ...` 写成了 `grep_test = Select-String ...`**——PowerShell 里赋值左侧带空格会被当成命令名，报 `CommandNotFoundException`，且错误信息夹在一堆输出中间容易被忽略。看到「项识别为 cmdlet」先查等号。
2. **PowerShell 管道里对 `git diff` 输出做 `ForEach-Object`/`Group-Object` 容易超时**（本轮 240 秒超时一次）。可靠做法：`git diff --numstat > file` 先落盘，再写脚本读文件统计——与 AGENTS.md §6「大目录不要用内联递归」同一类。
3. **长的多行 `foreach` 内联命令在 GBK 控制台下易被截断/乱码**（本轮一次 5 提交循环无输出）。写成 `.ps1` 文件再执行，稳定。

另：`Select-String -Encoding UTF8` 对中文行输出正常，但 `Write-Host` 拼接 `Substring` 前要先 `Trim()` 并夹紧长度，否则中文字符按字节截断会出乱码。

## 11. 复算清单

所有数字的出处，可直接复制执行（仓库根目录）：

```powershell

# 改动规模
git diff --numstat v1.0.5..HEAD > numstat.txt
(Get-Content numstat.txt | Where-Object { $_ -match '\S' }).Count   # 170 个文件条目

# 拆分幅度
(git show v1.0.5:coworker/server/app.py | Measure-Object -Line).Lines          # 2812
(Get-Content coworker/server/app.py | Measure-Object -Line).Lines              # 128
(git show v1.0.5:coworker/connectors/integration_tools.py | Measure-Object -Line).Lines  # 4519
(Get-Content coworker/connectors/integration_tools.py | Measure-Object -Line).Lines      # 239

# 端点守恒

# 豁免条数
```
