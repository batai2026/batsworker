## 1. 项目分析

对 OpenWorker 0.2.1（开源 AI 桌面协作助手，Andrew Ng 团队，MIT 许可）做了全库逆向分析：

- **技术栈**：Tauri（Rust 壳）+ React 18/TS/Vite SPA + Python 3.10+ FastAPI 本地服务（sidecar 模式）+ Rust whisper.cpp 语音离线转写；本地优先，模型自带 key（OpenAI/Anthropic/GLM/DeepSeek/Ollama 等 20 个注册提供商）。
- **核心子系统**：自研 Agent 引擎 `TurnEngine`（约 2000 行，回合循环 + 流式 + 压缩 + 持久化恢复）；五模式权限引擎与硬底线（含 OPE-114"取回即执行"来源底线、Auto-Approve LLM 评审员及熔断）；约 40 个连接器（三条认证路径 + 云中继）；MCP 客户端（OAuth 2.1 + DCR）；自动化调度器与跨会话 Inbox；哈希链防篡改的多人协作看板；声明式 Persona/技能体系。
- **工程质量**：后端 127 个测试文件、进程内 FakeSlack 测试架、72 个封闭式 Playwright e2e、代码内大量带日期的决策注释；前端为 2400 行单文件 App.tsx（无路由/状态库），文档目录与 README 描述不符（已在本会话补齐）。

## 3. GUI 界面中文化（i18n）

零依赖 i18n 方案（约 300 行基础设施），**英文原文即 key**：

- **架构**：`surfaces/gui/src/i18n/index.tsx` 提供 `I18nProvider`（挂载于 `main.tsx`）+ `useI18n()` hook；语言持久化于 localStorage（`ow.lang`），默认跟随浏览器语言；插值支持 `t("{n} runs", { n })`。
- **词典**：`src/i18n/zh/{app,shell,settings,cards}.ts` 四个区域文件（由 `zh/index.ts` 合并），共 **769 条**；查不到的键回退英文，英文模式与改造前逐字节一致（既有测试零改动通过）。
- **设置入口**：设置 ▸ 通用 ▸ 界面语言（English / 中文（简体）），即时生效。
- **覆盖范围（735 个调用键，校验全绿）**：启动闪屏、侧边栏、输入框（语音/附件/模式菜单/用量）、转录（评审员拦截卡/记忆通知）、全部审批与提问卡片、设置全部卡片、收件箱、自动化页面、活动页、右侧栏、首次引导、连接器主页面、文件夹流程、搜索、团队聊天等全部主流程。
- **刻意保留英文**：发给 agent 的任务提示词（模型对英文指令更稳，决策已文档化）、模型/提供商/连接器专有名词。
- **未覆盖（次级页面，约 6600 行）**：连接器详情页（Slack/Gmail/GitHub/HubSpot/日历）、添加连接弹窗、自定义 MCP、ManageTabs、SkillsTab、PersonasTab、Persona 详情页、看板全屏、GalleryModal、ProviderSetup 表单。续作方法见 §4 的护栏说明。

## 4. 质量护栏：i18n 进 CI（建议 9）

三层护栏全部接入现有 GitHub Actions（`ci.yml` 的 `gui-unit` job）：

1. **Python 校验器进 CI**：`surfaces/gui/scripts/check_i18n.py`（纯标准库）在每次 push/PR 强制校验"源码 `t()` 键 ⇆ 词典"双向一致（缺失 / 失效条目 / 变量引用白名单）；本地入口 `npm run i18n:check`。
2. **类型层（tsc 期防 typo）**：词典用 `satisfies` 保留字面量键推断；`MessageKey = keyof typeof zhDict`（约 760 个键的联合类型）；`t()` 签名收紧为 `(key: MessageKey, params?) => string`（`TFunction`）——**字面量键拼错即编译失败**；约 27 处动态调用点显式 `as MessageKey` 或改用类型化常量；透传 `t` 的辅助函数统一 `TFunction` 类型（严格模式逆变要求）。
3. **防腐化测试**：`src/i18n/i18n.test.ts`（插值、英文回退、空翻译守卫、**跨文件键漂移守卫**）+ `e2e/i18n.spec.ts`（中文模式渲染断言 + 无英文回退残留 + 设置页实时切换）。

## 6. 验证结果

| 关卡 | 结果 |
|---|---|
| `npx tsc --noEmit` | **0 错误**（首轮暴露 3 处，修复后归零） |
| `npm test`（vitest） | **141/141**（21 个文件，含新 i18n 套件 7 项） |
| `npm run e2e`（Playwright chromium） | **221/223**；剩余 2 个为并行负载下的计时抖动（Toast 5 秒自动消失类用例），单独重跑两次均通过 |
| `python scripts/check_i18n.py` | 735 调用键 / 769 词典条目，全绿 |

**验证过程发现并修复的问题**（多数是本地无 CI 期间的盲区）：

1. **SettingsView 导航崩溃炸弹**：`tabs.map((t) => ...)` 回调参数遮蔽翻译函数 `t`，回调内 `t(t.label)` 即对对象调用——打开设置页必崩（中英文皆崩）。改名 `tb` 修复。*教训：回调/定时器变量不得命名为 `t`（另有 3 处同类隐患已一并改名 `ta`/`tmpl`/`poll`/`u`）。*
2. **英文排版保真回归**：`&rsquo;` 弯撇号被转成直撇号、英文单复数被合并（`1 folder`→`1 folders`）——破坏"英文逐字节不变"承诺，被 6 个既有 e2e 抓住。已恢复弯撇号键并补 8 处单复数分支（`1 folder`/`1 run`/`1 new run`/`1 entry`/`1 tool call`/`1 more item`/`1 worker`/`1 project command allowance`）。
3. **词典文件被补丁脚本写坏**：增量补丁重建时回填 `Record<string, string>` 标注导致 cards.ts 字面量键全部退出 `MessageKey` 联合（409 个编译错误）；插入锚点撞上 `satisfies` 结尾。已修复，词典头部必须保持无标注。
4. **cards.ts 重复键**（TS1117，仅 tsc 可见）与 **2 处可空参数**（`standingTarget!`/`info.pages!`，运行时已有守卫）。
5. **预先存在的 e2e flake**：`nav-collapse` 在 React 挂载前按 ⌘B 丢失按键——加 `.sidebar` 可见等待修复。
6. **我自己的 i18n spec 断言缺陷**：`getByText("通用")` 命中两元素触发 strict mode，改用 `getByRole`。
